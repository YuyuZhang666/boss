# 《老板，这个你来》微信小游戏 MVP 设计规格

- 状态：已确认，等待规格审阅
- 日期：2026-08-20
- 产品形态：微信小游戏
- 屏幕方向：竖屏
- 首版目标：可玩的核心 MVP
- 技术基线：Cocos Creator 3.8 LTS、TypeScript、2D

## 1. 产品摘要

《老板，这个你来》是一款面向年轻职场用户的轻策略微信小游戏。玩家扮演公司“基层整改观察员”，在 AI 经营审计系统赋予的有限权限下，把适合管理层处理的一线任务提交给老板，并阻止老板用开会、甩锅、外包、改需求等方式逃避工作。

游戏的核心乐趣不是机械点击或单纯折磨老板，而是：

> 在保证公司正常运转的情况下，用有限的整改规则让老板完成董事会要求的一线任务。

产品采用现代、可爱、搞笑、轻松的表达方式。职场讽刺保持温和，不影射具体公司、品牌或现实人物。

## 2. MVP 目标与成功标准

MVP 只验证一个核心问题：

> “选择适合老板的任务，并在老板逃避时及时反制”是否有持续三分钟的策略乐趣。

成功标准：

1. 新玩家在首局一分钟内理解任务分配和规则反制。
2. 一局完整时长约三分钟，包含开局目标、任务调度、逃避反制和日报结算。
3. 玩家不能通过无脑把所有任务交给老板稳定获胜。
4. 老板的动作、表情和台词能在不阅读长文本的情况下传达当前行为。
5. 同一套内容能够支撑至少三个难度递进的工作日。
6. 构建产物能够在微信开发者工具和真实微信客户端完成完整对局。

## 3. MVP 范围

### 3.1 包含内容

- 一个 Q 版老板角色。
- 一间可动态反馈状态的老板办公室。
- 一个首次进入的短剧情动画。
- 三个逐步提高难度的工作日。
- 二十种任务。
- 五种老板逃避行为。
- 三种整改规则。
- 六种随机事件。
- 四项核心数值。
- 一套动态 CEO 整改日报。
- 六个结算称号。
- 本地进度、设置和最佳成绩存储。

### 3.2 明确不包含

- 多老板收集与角色养成。
- 微信好友排行榜和开放数据域。
- 付费、广告、登录和云存档。
- 多人玩法。
- 复杂剧情分支。
- 关卡编辑器。
- 3D 场景和物理系统。
- 需要后台服务才能进行的核心玩法。

这些能力在核心循环验证后另行设计，不提前预埋复杂业务。

## 4. 世界观与首次进入

公司经营出现问题，董事会启用 AI 经营审计系统，并启动“管理层下沉整改计划”。玩家是普通项目成员，被授予“整改任务提交权限”，可以提交真实一线任务，但没有直接命令老板的权力。

首次进入流程控制在 20 至 30 秒：

1. 会议室大屏显示“经营效率审计完成”。
2. 系统公布 CEO 一线参与度为 3.2%。
3. 老板质疑数据，AI 告知整改方案已由董事会通过。
4. 画面切到玩家电脑，显示“已获得整改任务提交权限”。
5. 玩家点击“开始今天的工作”进入第一天。

剧情可以点击跳过。完成首局后再次进入，默认显示简洁首页和“继续整改”，不重复强制播放剧情。

## 5. 单局体验

每局代表一个工作日，游戏内时间从 09:00 快进到 18:00，真实时长目标为 180 秒。

### 5.1 单局流程

1. 显示当天整改目标和三种可用规则。
2. 员工持续提交任务卡。
3. 玩家查看任务并选择“交给员工”或“提交老板”。
4. 交给员工的任务按员工效率结算；提交老板的任务进入老板队列。
5. 老板可能正常工作，也可能进入逃避预警。
6. 玩家决定是否消耗整改权限进行反制。
7. 任务完成、超时或逃避成功后更新核心数值。
8. 18:00 停止生成新任务并结算仍在处理的任务。
9. 生成 CEO 整改日报、评级和玩家称号。

### 5.2 三日内容

| 工作日 | 目标 | 玩法作用 |
| --- | --- | --- |
| 第一天 | 老板亲自完成 3 项任务 | 教学，低压力任务为主 |
| 第二天 | 老板完成工作量达到 35% | 增加紧急任务和逃避频率 |
| 第三天 | 公司经营不低于 50，并完成整改目标 | 要求同时平衡经营与整改 |

第三天通关后开放自由重玩。重玩随机化任务顺序和事件，不增加新的系统。

## 6. 核心数值

所有数值范围为 0 至 100，具体变化量放在配置中，以下为首版基线。

| 数值 | 初始值 | 作用 |
| --- | ---: | --- |
| 公司经营 | 70 | 任务超时、错误分配和高成本行为会降低；归零立即失败 |
| 整改进度 | 0 | 老板亲自完成有效任务后提高；决定当天目标是否完成 |
| 老板面子 | 65 | 高于 80 时更容易死撑，低于 20 时更容易摆烂 |
| 董事会信任 | 50 | 合理整改会提高；无效折腾和经营恶化会降低最终评级 |

老板面子不是越低越好。30 至 70 是相对健康区间；过高增加“死撑”行为，过低增加消极和记仇台词，但 MVP 不实现跨日惩罚链。

玩家每天拥有 5 点整改权限：

- 责任链追溯：消耗 2 点。
- 调取原始需求：消耗 1 点。
- 成本与工时审计：消耗 1 点。

剩余权限不会带到下一天。

## 7. 任务系统

### 7.1 任务字段

每个任务配置包含：

- 唯一 ID。
- 部门。
- 标题和一句话描述。
- 工作量：1 至 5。
- 专业度：1 至 5。
- 紧急度：1 至 5。
- 老板适配度：1 至 5。
- 截止时间。
- 员工处理基础成功率。
- 老板处理基础成功率。
- 完成、超时和失败的数值变化。
- 可触发的老板台词标签。

任务状态严格限制为：`待决策`、`员工处理中`、`老板队列中`、`老板处理中`、`已完成`、`已失败`、`已超时`。

### 7.2 二十种任务的内容分布

| 部门 | 任务示例 | 主要策略点 |
| --- | --- | --- |
| 研发 | 支付接口故障、线上崩溃、服务器扩容、修改按钮颜色 | 紧急度与专业度冲突 |
| 产品 | 客户临时加功能、需求口径冲突、数据指标定义 | 容易触发改需求和战略升级 |
| 运营 | 发布会 PPT、公众号文案、直播活动事故 | 截止时间短 |
| 销售 | 大客户投诉、续约折扣、超范围交付承诺 | 老板适配度高 |
| HR | 核心员工离职、招聘审批、团队冲突 | 面子和经营联动 |
| 财务 | 现金流异常、发票问题、供应商付款 | 外包和成本风险 |
| 行政 | 咖啡机坏了 | 搞笑干扰项，老板适配度极低 |

任务生成采用可复现的种子随机数。每局使用预设难度曲线：前 30 秒低压、中段增加并发、最后 45 秒加入一项高紧急任务。屏幕待决策任务最多保留 4 项，老板任务队列最多 3 项，避免无脑堆积。

## 8. 老板行为 AI

老板采用有限状态机，状态为：

`待机 → 接收任务 → 工作中/逃避预警 → 被反制/逃避成功 → 完成或失败 → 待机`

逃避行为必须先显示 1.2 至 1.8 秒预警。预警包含动作、表情、气泡和规则按钮提示，但不直接显示正确答案。

| 逃避行为 | 效果 | 主要反制 |
| --- | --- | --- |
| 开会 | 暂停当前任务并消耗公司工时 | 成本与工时审计 |
| 甩锅 | 将老板任务转给员工 | 责任链追溯 |
| 外包 | 花费公司经营值快速处理 | 成本与工时审计 |
| 改需求 | 降低完成标准，但可能损失信任 | 调取原始需求 |
| 战略升级 | 把小任务变成长会议 | 调取原始需求 |

逃避不是一律有害：高专业度紧急任务允许合理外包，跨部门重大事项允许有效会议。玩家错误反制合理行为时，会损失董事会信任或公司经营。

行为选择由任务标签、老板面子、当前时间、队列长度和当天难度共同决定。随机结果使用对局种子，便于复现问题和自动平衡测试。

## 9. 随机事件

每局随机触发 1 至 2 个事件，同一事件一局最多出现一次：

1. 董事会旁听：老板效率提高，甩锅概率降低。
2. 大客户到访：生成高适配度接待任务。
3. 秘书代做：玩家选择忽略或举报，分别影响进度和信任。
4. 临时团建：短时间降低员工处理效率。
5. 高尔夫邀约：接近下班时触发提前离岗预警。
6. 咖啡机故障：老板短暂离开座位，产生轻微节奏干扰。

事件采用覆盖式修正，不永久改写任务或角色配置。事件结束后必须恢复原始参数。

## 10. 结算与评级

18:00 生成“CEO 整改日报”，至少统计：

- 老板亲自工作时长。
- 老板完成任务数量与工作量。
- 主持会议和有效会议次数。
- 尝试及成功甩锅次数。
- 外包次数和成本。
- “这个很简单”出现次数。
- 公司经营、整改进度、老板面子和董事会信任。

基础评级权重：整改进度 40%、公司经营 25%、董事会信任 20%、老板面子平衡度 15%。当天硬目标未完成或公司经营归零时不授予 A 级以上评价。

SSS 评级要求同时满足：整改目标完成、公司经营不低于 70、董事会信任不低于 70、老板面子处于 30 至 70，且没有未处理的高紧急任务。

首版称号：

- 温和改革派。
- 赛博周扒皮。
- 会议终结者。
- 甩锅回旋镖大师。
- 公司还活着就行。
- 让老板心甘情愿打工的人。

称号由明确的统计条件生成，不调用在线 AI。

## 11. 竖屏界面设计

界面采用上下分层，所有关键操作位于单手拇指易触区域。

### 11.1 顶部状态区，约 12%

- 时间进度和当前时间。
- 当天整改目标。
- 四项数值的紧凑入口。
- 数值变化用短暂浮字反馈，避免常驻信息拥挤。

### 11.2 办公室舞台，约 48%

- 老板和办公桌是视觉中心。
- 三块屏幕、手机、咖啡、杂志和绿植提供状态反馈。
- 任务提交时文件夹弹射到桌面。
- 队列变长时桌面逐渐凌乱。
- 逃避预警优先使用角色动作和气泡，不遮挡老板。

### 11.3 任务区，约 25%

- 横向任务卡队列，一次突出一张。
- 默认显示部门、标题、紧急度和老板适配度。
- 点击展开工作量、专业度、剩余时间和描述。
- 操作按钮为“交给员工”和“提交老板”。

### 11.4 整改规则区，约 15%

- 三个规则按钮常驻底部。
- 长按显示规则说明，点击立即使用。
- 可用反制只做轻微跳动提示，不自动替玩家决策。
- 所有点击目标满足移动端易触尺寸，并避开系统安全区域。

界面基于安全区和锚点自适应，不依赖固定像素位置。重点覆盖 16:9 至 21:9 的常见竖屏比例；超长屏增加留白，不拉伸办公室和角色。

## 12. 视觉、动画与声音

### 12.1 视觉语言

- 风格：现代扁平插画，配合轻微 2.5D 层次。
- 背景色：暖米白 `#FFF6E8`。
- 主色：薄荷绿 `#70D6B4`。
- 强调色：珊瑚橙 `#FF7A6E`。
- 辅助色：暖黄 `#FFC857`。
- 警告色：柔和红 `#EF6461`。
- 正文字色：深灰紫 `#3D3A45`。

卡片和按钮使用大圆角、柔和阴影、清晰描边和有限的半透明效果。正文使用系统可用中文字体，避免引入未授权字体；标题通过字重、描边和排版营造圆润感。

### 12.2 老板角色

老板采用头大身小的 Q 版比例，性格是“自信、爱面子、擅长说宏观话”。不使用现实企业家特征。首版至少包含待机、看手机、喝咖啡、接任务、工作、震惊、心虚、开会、甩锅、外包、改需求、摆烂和完成任务动作。

### 12.3 动效原则

- 点击反馈：80 至 120 毫秒。
- 卡片进出：180 至 260 毫秒。
- 任务弹射：约 300 毫秒，带轻微挤压和回弹。
- 逃避预警：1.2 至 1.8 秒，必须清晰可读。
- 数值浮字不超过 800 毫秒，不阻塞操作。

装饰动画包括咖啡蒸汽、屏幕闪烁、纸张抖动和绿植轻摆。低性能模式可关闭粒子、动态阴影和次要装饰动画，玩法反馈动画不可关闭。

### 12.4 声音

- 任务到达、提交、规则盖章、反制成功、数值警告和结算各有短音效。
- 老板台词以气泡和拟声为主，MVP 不制作全语音。
- 首次用户交互后再启动背景音乐。
- 设置中提供音乐和音效独立开关，切后台时暂停音频。

## 13. 教学设计

首局不使用长篇教程：

1. 第一张任务只高亮任务卡和分配按钮。
2. 老板第一次甩锅时，游戏短暂停顿并高亮“责任链追溯”。
3. 使用规则后立即恢复实时流动。
4. 第一次错误分配只提示原因，不施加致命惩罚。
5. 完成第一天后取消所有强制引导，仅保留长按说明。

教学暂停期间游戏计时、任务截止时间和动画状态全部暂停，恢复后不补算时间。

## 14. 技术架构

### 14.1 模块边界

| 模块 | 职责 |
| --- | --- |
| `GameFlow` | 启动、进行、教学暂停、普通暂停、结算和重开 |
| `GameClock` | 工作日时间、固定节拍和截止时间 |
| `TaskSystem` | 任务生成、队列、分配、处理和结算 |
| `BossAI` | 老板状态机、行为选择和预警窗口 |
| `RuleSystem` | 权限点、反制匹配、消耗和结果 |
| `CompanyState` | 四项数值及原子化变更 |
| `EventSystem` | 随机事件调度、临时修正和恢复 |
| `ResultSystem` | 统计、评分、日报和称号 |
| `SaveService` | 版本化本地存档和损坏恢复 |
| `WeChatAdapter` | 微信生命周期、存储、分享和设备信息 |
| `AudioService` | 音乐、音效、静音和前后台处理 |

逻辑层不直接引用微信全局对象。只有 `WeChatAdapter` 可以调用微信 API，方便在编辑器中运行测试并集中处理兼容差异。

### 14.2 数据流

用户操作先形成命令，由对应系统验证，再统一修改状态，最后发布只读事件供 UI 和动画响应：

`输入 → 命令验证 → 游戏状态变更 → 领域事件 → UI/动画/声音`

动画不得直接修改公司数值或任务状态。状态变更必须通过系统方法完成，保证表现中断、切后台或跳过动画时结果仍一致。

### 14.3 配置与存档

任务、事件、规则、台词、难度和数值使用 JSON 或 TypeScript 静态配置。启动时进行结构校验；单条配置异常时记录错误并跳过该条，核心配置缺失时进入可读错误页而不是黑屏。

存档包含模式版本号、已解锁天数、设置、最佳成绩和当前暂停对局。写入采用“新值校验成功后替换旧值”的方式；解析失败时保留设置并重置进度，同时提示玩家。

## 15. 微信小游戏落地约束

1. 使用 Cocos Creator 3.8 LTS 的微信小游戏构建目标和 TypeScript。
2. 构建方向固定为 `Portrait`，正式包使用用户提供的微信小游戏 AppID。
3. 不使用 DOM、WebView、浏览器扩展 API、Node.js 运行能力或运行时动态脚本。
4. 主包目标不超过 3.5 MB，为平台 4 MB 限制预留空间。
5. 优先通过功能裁剪、图集压缩和音频压缩控制包体；确有需要时使用官方支持的引擎分离、初始场景分包或远程资源。
6. 远程地址只托管图片、音频和数据等资源，不下载执行脚本。
7. 核心三日玩法不依赖网络请求；远程资源失败时显示重试并保留轻量本地加载页。
8. 切后台立即暂停游戏时钟、任务截止时间和音频；回到前台由玩家主动继续。
9. 平台存储、分享等调用失败只降级对应功能，不阻断单机对局。
10. 不手工修改引擎生成代码来制造不可复现的发布包；必要适配放在版本化构建模板或平台适配层。

正式预览和发布依赖用户提供有效 AppID、开发者权限以及至少一台 iOS 和一台 Android 真机。这些属于发布所需外部条件，不由游戏代码替代。

## 16. 性能预算

- 正常玩法目标 60 FPS；参考中低端设备的最低可接受稳定帧率为 30 FPS。
- 任务卡、气泡、浮字和常用特效使用对象池。
- 办公室和 UI 使用图集减少绘制批次。
- 避免在每帧循环中创建数组、字符串和临时对象。
- 游戏规则以固定节拍更新，不把所有计算放在逐帧更新中。
- 同屏活动任务卡不超过 4 张，老板队列不超过 3 项，装饰粒子设置硬上限。
- 进入结算或重开后释放上一局临时节点、计时器和事件监听。
- 连续十局后内存不得呈线性增长，回到首页后的内存应接近首局前稳定值。

## 17. 错误处理

- 配置加载失败：显示可读错误信息并允许重试。
- 非核心资源失败：使用默认图块或静音降级，不黑屏。
- 存档损坏：保留设置，重建进度并提示。
- 微信 API 不可用：编辑器使用适配层模拟实现，真机降级对应功能。
- 重复点击：命令层使用状态锁和幂等检查，避免重复扣除权限。
- 动画被中断：逻辑结果由状态机保证，UI重新从当前状态渲染。
- 意外切后台：立即保存快照，恢复时不补算离线时间。

## 18. 测试策略

### 18.1 自动测试

- 任务状态转换测试。
- 老板所有行为路径和反制结果测试。
- 权限不足、重复点击和超时边界测试。
- 核心数值上下限测试。
- 暂停与恢复一致性测试。
- 存档版本、损坏和迁移测试。
- 使用固定种子批量模拟对局，确认三天均可获胜且无单一必胜策略。

### 18.2 编辑器与构建测试

- Cocos 编辑器预览无未处理异常。
- 能生成完整 `wechatgame` 目录。
- 生成的 `game.json` 为竖屏配置。
- 生成的 `project.config.json` 使用正确 AppID。
- 微信开发者工具编译无错误和缺失资源。

### 18.3 真机测试

- 至少一台 iPhone 和两档 Android 设备完成完整三日流程。
- 覆盖 16:9、约 19.5:9 和更长竖屏比例。
- 验证触控、安全区、音频、震动、前后台、锁屏和网络中断。
- 连续完成十局，无卡死、黑屏、结算丢失或持续内存增长。
- 中低端参考设备能够以至少 30 FPS 稳定完成对局。

## 19. 交付验收门槛

只有以下条件全部满足，MVP 才能标记完成：

1. 三个工作日均可从开局进行到日报结算。
2. 二十种任务、五种逃避行为、三种规则和六种事件均可触发。
3. 教学可以完成、跳过，且不会破坏计时状态。
4. 无法通过持续选择同一个按钮稳定获得最高评价。
5. Cocos 构建和微信开发者工具编译通过。
6. 微信真机可以进入、游玩、切后台恢复并正常结算。
7. 主包、资源来源和脚本加载符合微信小游戏限制。
8. 真机布局、性能和十局稳定性达到本规格要求。
9. 不存在阻塞游戏的已知 P0/P1 缺陷。
10. 构建步骤、测试设备、开发者工具版本和已知限制记录在交付说明中。

浏览器预览成功不能替代微信开发者工具和真机验收。

## 20. 推荐实现顺序

实现计划应按风险优先推进：

1. 创建最小 Cocos 工程并尽早打通空场景微信构建。
2. 完成无美术的可测试规则模拟层。
3. 完成任务调度、老板状态机和三种反制。
4. 接入竖屏办公室主界面和教学。
5. 接入角色动画、动效、声音和完整配置内容。
6. 完成日报、存档和三日难度。
7. 进行微信开发者工具、真机、性能和包体收口。

第一步就验证微信构建，避免在玩法完成后才发现平台配置或工具链问题。
